Vikunja supports managing [tasks](/help/tasks) via the [caldav VTODO](https://tools.ietf.org/html/rfc5545#section-3.6.2) extension.

You can find your CalDAV connection details in your [Settings](/help/settings) under the CalDAV tab.

<Screenshot src="caldav-connection-details" alt="CalDAV connection details in settings" />

## Authentication

When you connect a CalDAV client, use your Vikunja **username** and one of the following as the password:

- **Your account password** — the easiest option, and the one we recommend whenever it works for you. Local accounts, including those provisioned via LDAP, can use their normal password directly. If your account signs in through an external identity provider (OIDC) — for example on <a href={VIKUNJA_CLOUD_LINK}>Vikunja Cloud</a> — the CalDAV settings tab shows a hint asking you to use a dedicated token instead, because your password isn't stored in Vikunja. Passwords also don't work when two-factor authentication is enabled on your account.
- **A dedicated CalDAV token** generated on the CalDAV settings tab. Use this if your account signs in via OIDC, or if you have two-factor authentication enabled.
- **An [API token](/help/settings#api-tokens) with the CalDAV permission group**, available from Vikunja **2.3.0** onwards. Use the token value (it starts with `tk_`) as the password. This is handy if you want to manage all your automation credentials in one place, or if you want a single token to cover both CalDAV sync and API access.

## Failed authentication and rate limits

From Vikunja **2.6.0** onwards, failed CalDAV authentication is limited per IP address. The default allows 10 failed attempts per minute, even when the instance's general rate limiter is disabled. After the limit is reached, CalDAV requests from that IP return `429 Too Many Requests` until the current minute has passed.

Normal sync traffic does not use up this limit. Requests without credentials only receive the usual authentication challenge, and successful requests are refunded from the counter. A client can send as many successful `PROPFIND` and `REPORT` requests as it needs.

If a client suddenly looks broken after several password or token errors, check its saved credentials and wait for the rate-limit window to reset. The same failed-authentication budget is shared with Vikunja's authenticated notification feeds from that IP.

## URLs

All URLs are located under the `/dav` subspace.

URLs are:

* `/principals/<username>/`: Returns URLs for project discovery. *Use this URL when connecting a new client.*
* `/projects/`: Used to manage [projects](/help/projects)
* `/projects/<Project ID>/`: Used to manage a single project
* `/projects/<Project ID>/<Task UID>`: Used to manage a task on a project

## Set up on iOS

<Callout type="info">
Syncing with iPhone and iPad needs Vikunja **2.2.0** or later.
</Callout>

Your Vikunja tasks show up in the Reminders app. Each project becomes a list.

First, create a CalDAV token in Vikunja:

1. Click your username in the top right corner and select **Settings**.
2. Open the **CalDAV** tab.
3. Copy the CalDAV URL at the top of the page and note your username shown below it.
4. Click **Create a CalDAV token** and copy the token. You won't see it again.

Then add the account on your iPhone or iPad:

1. Open the **Settings** app and go to **Apps** → **Calendar** → **Calendar Accounts**. On iOS 17 and earlier, go to **Calendar** → **Accounts** instead.
2. Tap **Add Account** → **Other** → **Add CalDAV Account**.
3. Fill in the fields:
   - **Server:** the CalDAV URL you copied, for example `https://vikunja.example.com/api/v1/dav/principals/yourname/`
   - **User Name:** your Vikunja username
   - **Password:** the CalDAV token
   - **Description:** any name, for example "Vikunja"
4. Tap **Next** and wait for iOS to verify the account.
5. Turn on **Reminders** and tap **Save**.

Open the Reminders app. Your Vikunja projects appear under the account's description. It can take a moment for the first sync to finish.

If verification fails, check that the Server field contains the full URL including `https://` and the trailing slash. After several failed attempts, Vikunja temporarily blocks further logins from your IP (see [rate limits](#failed-authentication-and-rate-limits)), so wait a minute before trying again.

## Supported properties

Vikunja currently supports the following properties:

* `UID`
* `SUMMARY`
* `DESCRIPTION`
* `PRIORITY`
* `CATEGORIES`
* `COMPLETED`
* `CREATED` (only Vikunja → Client)
* `DUE` ([Due date](/help/dates-and-reminders))
* `DURATION`
* `DTSTAMP`
* `DTSTART`
* `LAST-MODIFIED` (only Vikunja → Client)
* `RELATED-TO` (parent/child relations)
* `RRULE` (Recurrence) (only Vikunja → Client)
* `STATUS` (only `COMPLETED` status, used to mark tasks as done)
* `VALARM` ([Reminders](/help/dates-and-reminders))

Vikunja **currently does not** support these properties:

* `ATTACH`
* `CLASS`
* `COMMENT`
* `CONTACT`
* `GEO`
* `LOCATION`
* `ORGANIZER` (disabled)
* `PERCENT-COMPLETE`
* `RECURRENCE-ID`
* `RESOURCES`
* `SEQUENCE`
* `URL`
